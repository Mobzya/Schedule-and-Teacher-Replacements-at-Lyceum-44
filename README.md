# Лицей №44 — расписание и замены

Telegram-бот расписания МБОУ «Лицей №44» г. Чебоксары, учебный год **2026/27**.

## Где работает бот

Основной деплой — **Cloudflare Workers (Python) + Cloudflare D1**. Telegram присылает события
через webhook: постоянно работающий сервер, Render и сервис «пинга» не нужны.

- Worker: `lyceum44-schedule-bot`.
- Адрес: https://lyceum44-schedule-bot.werhants.workers.dev.
- Проверка доступности: [`/health`](https://lyceum44-schedule-bot.werhants.workers.dev/health).
- Telegram webhook: `POST /telegram`, с проверкой секретного заголовка.
- Данные: D1 `lyceum44-schedule` — пользователи, классы, друзья, расписание, замены,
  источники, очередь уведомлений и состояния админских диалогов.
- Аватарки: Workers Static Assets, каталог `public/avatars/`.

Worker использует прямые запросы к Telegram Bot API. Aiogram/aiohttp нужны только
для альтернативного локального запуска. Старые Render/Docker-файлы сохранены для
совместимости, **они не описывают основной работающий деплой**.

## Возможности

- Сегодня/завтра, просмотр недели и выбор даты; класс и профиль.
- Замены с предметом, кабинетом, учителем и отменами уроков.
- Напоминания перед уроками, утренняя сводка и уведомления о заменах.
- Короткое вечернее поздравление перед праздником или первым днём каникул, с уведомлением об отсутствии уроков.
- Календарь официальных каникул и неучебных дней лицея.
- Список друзей: текущий и следующий урок, компактное перелистывание.
- Админка источников, ручная проверка, управление публикацией и отдельная рассылка.
- 14 сезонных/праздничных аватарок с автоматической сменой.

Меню компактное: расписание, замены, друзья, настройки. Выбор класса, уведомления,
звонки, помощь и админ-панель доступны из настроек. Большинство действий редактируют
одну панель вместо отправки новых сообщений.

## Как обновляются расписание и замены

[Расписание](https://docs.google.com/spreadsheets/d/1yFbLC3cXH_Xuci_VBvxGKt9n6_QZpmTg/edit)
загружается по отдельной CSV-вкладке для каждой параллели 5–11 классов.

[Книга замен](https://docs.google.com/spreadsheets/d/1bZlIyg9_0JYLnN2WTD3SMxg4zHWe-PaqWDGYnZV1hEg/edit)
содержит месячные вкладки. Важно: **`gid=1372611677` — сентябрьский архив**, а не
ссылка, которая автоматически означает «актуальные замены».
Ноябрьская вкладка: [`gid=1397336121`](https://docs.google.com/spreadsheets/d/1bZlIyg9_0JYLnN2WTD3SMxg4zHWe-PaqWDGYnZV1hEg/edit?gid=1397336121).

Автоматика:

1. Раз в 6 часов читает лёгкий публичный список вкладок книги.
2. Находит вкладки вида «Замена ноябрь 2026», «Замена декабрь 2026» и т. п.
   только для настроенного учебного года; копии и прошлогодние вкладки не подключает.
3. Добавляет новые месяцы отдельными источниками и импортирует CSV по одному.
   Не скачивает всю книгу XLSX в Worker.
4. Текущий автоматически добавленный месяц имеет приоритет: обычно проверяется
   раз в 4 минуты. Остальные источники обходятся по кругу, не блокируя друг друга.

Вручную добавленная ссылка с `gid` продолжает означать ровно одну указанную вкладку.
Отключённые администратором источники не включаются заново при обнаружении вкладок.

При временной ошибке Google или парсинга последний успешно импортированный snapshot
остаётся в D1. Ошибка списка вкладок повторно проверяется через 15 минут и не останавливает
обычный импорт уже известных источников. Неизменившийся snapshot не перезаписывается.
Название месяца в декоративной строке не заменяет настоящие даты внутри таблицы.

Это не абсолютная гарантия: закрытый доступ, переименование вкладок, изменение формата,
квоты Cloudflare или недоступность Telegram/Google требуют диагностики.
Подробности: [источники и устранение неполадок](docs/replacements.md).

## Фоновые задачи Cloudflare

| Cron (UTC) | Назначение |
| --- | --- |
| `*/2 * * * *` | Один импорт либо отдельная проверка новых месячных вкладок |
| `1-59/2 * * * *` | Уведомления: до двух активных пользователей и небольшая очередь отправки |
| `3-59/10 * * * *` | Проверка сезонной аватарки |

Календарь, даты уроков и выбор оформления считаются по **Europe/Moscow**.
Импорт, уведомления и аватарки разделены по вызовам, чтобы укладываться в бюджет CPU.
В неучебные дни учебные уведомления не создаются, устаревшие сообщения из очереди
не отправляются. Административные рассылки работают и в каникулы.

С **19:00 по Москве до полуночи** бот отправляет короткое поздравление, если завтра
праздник без учёбы или первый день каникул по календарю лицея. Обычные и перенесённые
выходные не вызывают поздравлений. Учитываются класс, дополнительные каникулы
первоклассников и распоряжения `/schoolday`; выпускникам не обещаются летние каникулы
вместо ГИА. Получатели — ученики с актуальным классом и хотя бы одним включённым
видом уведомлений, пока расписание опубликовано. Повторный Cron или перезапуск не
создаёт новое поздравление на ту же дату. После полуночи запоздавшее поздравление
удаляется из очереди. Дополнительная настройка Cron или миграция D1 не требуется.

Работа рассчитана на небольшой лицейский бот и бесплатные квоты Cloudflare, без
обещания SLA или неизменности тарифов. При росте аудитории небольшой пакет уведомлений
может не успеть обойти всех до урока: очередь повторяет уже сформированные сообщения,
но не гарантирует своевременного формирования каждого напоминания.

## Обновление уже работающего бота

Нужны Node.js/npm, [uv](https://docs.astral.sh/uv/) и авторизация в нужном аккаунте Cloudflare.

```bash
bash scripts/cloudflare-update.sh --dry-run
bash scripts/cloudflare-update.sh
```

Вторая команда проверяет сборку, применяет только новые D1-миграции и публикует Worker
с аватарками. Существующие секреты, пользователи и webhook сохраняются.
Для обычного обновления не нужно повторно вводить bot token или запускать initial deploy.

Логи:

```bash
npx wrangler tail lyceum44-schedule-bot
```

Не публикуйте полные логи запросов: они могут содержать заголовок webhook.

## Первый деплой в свой аккаунт

```bash
bash scripts/cloudflare-deploy.sh
```

Скрипт поможет авторизоваться, создаст/найдёт D1, применит миграции, проверит сборку,
запросит секреты, опубликует Worker и подключит Telegram webhook.
Для своего аккаунта выберите собственное имя базы и binding в `wrangler.jsonc`;
UUID базы этого проекта не даёт доступа к ней.

Секреты Cloudflare: `BOT_TOKEN`, `ADMIN_IDS`, `TELEGRAM_WEBHOOK_SECRET`.
Обычные настройки — в `wrangler.jsonc`. Production не читает локальный `.env`.
Перед включением webhook остановите все запуски long polling с тем же токеном.

Подробная инструкция: [Cloudflare deploy](docs/cloudflare-deploy.md).

## Администрирование

`Настройки → Админ` или `/admin`:

- **Источники** — добавить таблицу, посмотреть результат последней проверки, включить/отключить источник.
- **Синхронизация** — проверить следующий источник, не разбирая все таблицы в одном Worker-вызове.
- **Публикация** — `waiting` / `ready` / `paused`; изменение не требует обязательной рассылки.
- **Рассылка** — отдельное объявление пользователям, с очередью и повторными попытками доставки.

Ручные исключения календаря (только для администраторов):

```text
/dayoff 2026-11-02 Дополнительный день отдыха
/schoolday 2026-10-26 0 Разовые занятия по понедельнику
/dayclear 2026-10-26
```

`0` означает понедельник, `6` — воскресенье. Исключения действуют на весь лицей.
Полные календари: [каникулы и праздники](docs/school-calendar.md),
[сезонные аватарки](docs/avatar-rotation.md).

## Локальная разработка и тесты

```bash
uv sync --all-groups
uv run --group local --with pytest==8.4.1 --with pytest-asyncio==1.1.0 pytest -q
uv run --group local python -m scripts.check_sources
uv run --group local python -m scripts.check_sources --replacements-only
```

Первая проверка использует временные базы и тестовые данные, не отправляет сообщения в Telegram.
Вторая скачивает реальные публичные таблицы во временную SQLite и проверяет импорт классов,
замен и отображение расписания; production D1 не изменяет.
Если основное расписание закрыто (HTTP 401), вариант `--replacements-only`
независимо проверяет импорт и отображение замен.

Локальный эмулятор Worker:

```bash
bash scripts/cloudflare-dev.sh
```

Для отдельных локальных экспериментов с aiogram скопируйте `.env.example` в `.env`,
задайте **отдельный тестовый токен** и выполните `uv run --group local python -m app.main`.
Не запускайте эту команду с production-токеном: polling удаляет webhook и конфликтует с Worker.

## Структура проекта

```text
cloudflare/worker.py       # Telegram webhook и Cron
cloudflare/migrations/     # Миграции D1

app/services/            # Импорт, календарь, расписание, уведомления, друзья, аватарки
app/db.py                # SQLite/PostgreSQL/D1

tests/                   # Автономные тесты

wrangler.jsonc           # Конфигурация Cloudflare без секретов
```

## Безопасность данных

Токен из старой публичной версии считается скомпрометированным — отзовите его через
BotFather и используйте новый. Не храните токены в Git, не коммитьте `.env`,
дампы D1, SQLite, резервные копии пользователей и логи Wrangler.
Удаление секрета только из текущего файла не отзывает его и не удаляет из истории Git.

[Перенос прежних пользователей](docs/cloudflare-deploy.md#перенос-старых-пользователей)
делается отдельно из доступной старой БД; Bot API не позволяет получить список всех подписчиков.
