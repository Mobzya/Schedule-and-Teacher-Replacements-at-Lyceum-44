# Сезонные аватарки

14 сдержанных вариантов отредактированы встроенным imagegen на основе второго присланного изображения:
тот же знак «44», перо, надписи «ЛИЦЕЙ / ЧЕБОКСАРЫ», композиция, звёздочка и линия. Меняются палитра
и небольшой тематический акцент. Неизменённые оригиналы и ранние варианты с персонажами не используются.

Готовые файлы: `public/avatars/*-strict-v1.jpg` (768×768, настоящий JPEG).
Исходники: `output/imagegen/avatars/originals/`. Промпты: `output/imagegen/avatars/prompts.json`.
Для изменения изображений использован imagegen; во время работы бота генерация и внешние API изображений не используются.

После замены исходника JPEG и общий обзор можно пересобрать без генерации:
`uv run python -m scripts.prepare_avatars` (нужен ImageMagick).
Для установки новой редакции уже выбранной темы увеличьте `ASSET_REVISION` и пересоберите файлы перед деплоем.

## Правило выбора

Всё считается по `TIMEZONE` бота (`Europe/Moscow`). Сезоны календарные:
декабрь–февраль, март–май, июнь–август, сентябрь–ноябрь.

Праздничный вариант имеет приоритет над сезонным и действует **ровно семь календарных дней**:
за три дня до праздника, в сам день и три дня после. Затем возвращается текущая сезонная аватарка.

| Тема | Дата | Интервал включительно |
| --- | --- | --- |
| Новый год | 1 января | 29 декабря — 4 января |
| День студента | 25 января | 22–28 января |
| День науки | 8 февраля | 5–11 февраля |
| 8 Марта | 8 марта | 5–11 марта |
| День космонавтики | 12 апреля | 9–15 апреля |
| Последний звонок | 25 мая | 22–28 мая |
| День защиты детей | 1 июня | 29 мая — 4 июня |
| День знаний | 1 сентября | 29 августа — 4 сентября |
| День учителя | 5 октября | 2–8 октября |
| Хэллоуин | 31 октября | 28 октября — 3 ноября |

25 мая — фиксированная дата оформления, а не утверждение о дате последнего звонка в лицее.
Праздники настраиваются в `HOLIDAYS` файла `app/services/avatars.py`. Если добавить пересекающиеся
интервалы, выигрывает первая тема в списке. В текущем наборе пересечений нет.

## Cloudflare

JPEG загружаются как Workers Static Assets вместе с проектом и доступны через binding `ASSETS`.
Они не хранятся в D1 и не раздувают Python snapshot. Внешний сервер, R2 и отдельный аккаунт Telegram не нужны.
Смена выполняется официальным Telegram Bot API `setMyProfilePhoto`, через новую multipart-загрузку JPEG,
потому что этот метод не принимает повторный `file_id` или ссылку на картинку.
Объект `photo` передаётся как JSON с `attach://avatar`; вложение — отдельный нативный JS `File`
в multipart-поле `avatar`, с явными именем `.jpg` и MIME `image/jpeg`.
Нативный JS-массив частей файла избегает ошибки конвертации Python-последовательностей в Pyodide.
Результат `workers.Response.blob()` предварительно разворачивается через `js_object`: SDK-обёртка
не является JS Blob и при прямой передаче в `File` создаёт недолговечный Python proxy.

Источники: [Telegram](https://core.telegram.org/bots/api#setmyprofilephoto),
[InputProfilePhotoStatic](https://core.telegram.org/bots/api#inputprofilephotostatic),
[Cloudflare Assets binding](https://developers.cloudflare.com/workers/static-assets/binding/).
Реализация приёма файла: [официальный исходник Telegram Bot API](https://github.com/tdlib/telegram-bot-api/blob/master/telegram-bot-api/Client.cpp).

Отдельный Cron `3-59/10 * * * *` проверяет оформление примерно раз в десять минут.
Без изменений календарной темы Telegram не вызывается и изображение не скачивается.
Это отдельная задача: загрузка фото не расходует лимит CPU импорта таблиц или уведомлений.
После установки текущая тема сохраняется в D1; перезапуск Worker не вызывает повторной установки.
При недоступности Telegram прежняя аватарка остаётся, следующая попытка — через 10 минут
или позже, если Telegram прислал `retry_after`. Код не удаляет старые фотографии.
Точное переключение в полночь не гарантируется: добавляется задержка Cron/Telegram, до десяти минут при штатной работе.
Клиент Telegram также может некоторое время показывать закэшированную аватарку.

Обновить проект и картинки: `bash scripts/cloudflare-update.sh`.
Только проверить сборку: `bash scripts/cloudflare-update.sh --dry-run`.
Первое изображение выбирается автоматически при ближайшем запуске Cron после публикации.
Новый или изменённый Cron распространяется по сети Cloudflare до 15 минут;
сразу после первого деплоя запуск в ближайшую минуту расписания может ещё не произойти.
Источник: [Cron Trigger propagation](https://developers.cloudflare.com/workers/configuration/cron-triggers/).

Проверка без вывода секретов:

```bash
npx wrangler d1 execute lyceum44-schedule --remote --command "SELECT key,value FROM app_state WHERE key LIKE 'avatar_%'"
```

`avatar_current` записывается **только после** подтверждения Telegram. Остальные поля:
`avatar_updated_at`, `avatar_retry_at`, `avatar_last_error` (тип, код и очищенная причина при HTTP 400/ошибке JS, без URL/токена).
Для отключения автоматики без удаления фото:

```bash
npx wrangler d1 execute lyceum44-schedule --remote --command "INSERT INTO app_state(key,value) VALUES('avatar_enabled','0') ON CONFLICT(key) DO UPDATE SET value='0'"
```

Для включения замените оба значения `0` на `1`. Чтобы принудительно повторить установку текущей темы,
после включения поставьте разовую заявку:

```bash
npx wrangler d1 execute lyceum44-schedule --remote --command "INSERT INTO app_state(key,value) VALUES('avatar_manual_pending','1') ON CONFLICT(key) DO UPDATE SET value='1'"
```

Она выполнится вместо одного ближайшего запуска проверки уведомлений (обычно в пределах двух минут),
с отдельным лимитом CPU; затем обычная обработка уведомлений продолжится. Ошибка заявки не блокирует очередь.
Состояние последней успешной аватарки при этом не удаляется.
Токен не нужен: эти операции выполняются авторизованным Wrangler.

## Локальный/Render режим

При `python -m app.main` тот же календарь проверяется отдельной задачей раз в десять минут.
Файлы берутся из `public/avatars/`, состояние — из настроенной SQLite/PostgreSQL.
Не запускайте локальный polling одновременно с Cloudflare webhook одного бота.
