# Деплой бота на Cloudflare Workers + D1

Для Cloudflare используется Python Worker с прямым Telegram Bot API через встроенный `fetch` и D1 (SQLite-совместимая база). Aiogram и aiohttp остаются только в локальном/Render-режиме и не попадают в Cloudflare bundle. Google Sheets тоже запрашиваются через Workers `fetch`; расписание, настройки пользователей, состояние публикации, FSM админки, рассылки и напоминания хранятся в D1.

## Быстрый вариант: один запуск

В проект добавлен интерактивный скрипт, который находит или создаёт D1, прописывает её ID в Wrangler-конфиг, сначала проверяет сборку Worker без публикации, затем накатывает миграции, публикует Worker, загружает Telegram-секреты и регистрирует webhook. Сначала в BotFather отзови засвеченный токен и останови Render/локальный polling, затем из корня репозитория выполни:

```bash
bash scripts/cloudflare-deploy.sh
```

При первом запуске подтверди Cloudflare login в браузере. Если `uv` ещё не установлен, скрипт установит его официальным установщиком; Node.js и npm должны быть установлены заранее. Скрипт попросит остановку старого polling (введи `STOP`), Telegram ID администратора и новый bot token. Секрет webhook он создаст сам; `.env` не читает, а секреты не записывает в файлы. Если ID D1 ещё не прописан в `wrangler.jsonc`, скрипт сначала найдёт базу `lyceum44-schedule` в аккаунте Cloudflare и привяжет её; только если такой базы нет, создаст новую.

В конце скрипт проверит `/health` и зарегистрирует webhook. Если деплой остановится на ошибке, не отправляй токен в чат: пришли только текст ошибки после удаления любых секретов.

Для последующих обновлений кода используй команду, которая сохраняет существующие секреты и webhook:

```bash
bash scripts/cloudflare-update.sh
```

Перед публикацией она проверит сборку. Только проверить сборку: `bash scripts/cloudflare-update.sh --dry-run`.
Скрипт рассчитан на уже созданную D1; перед публикацией он применяет ещё не выполненные миграции.
Режим `--dry-run` ничего не меняет в D1 и не публикует Worker.

В `public/avatars/` лежат 14 готовых JPEG для оформления бота. Wrangler публикует их как Static Assets
с binding `ASSETS`; переносить их в D1/R2 не нужно. Отдельный Cron `3-59/10 * * * *` меняет аватарку
по московской дате, не мешая импорту и уведомлениям. Подробности и отключение: [avatar-rotation.md](avatar-rotation.md).

## Ограничение бесплатного плана

У Workers Free лимит CPU — 10 мс на один запрос или запуск Cron. Это не 10 мс общего времени ожидания сети: запросы к Telegram/Google Sheets ожидают отдельно, но Python-парсинг и SQL-логика тратят CPU. Поэтому Cron обрабатывает один источник раз в 2 минуты и до двух пользователей с уведомлениями в отдельном запуске раз в 2 минуты. Полный круг синхронизации занимает примерно две минуты на каждый включённый источник. Рассылки и напоминания сначала попадают в постоянный D1 outbox и постепенно отправляются с повторами; ошибки одного источника не блокируют остальные.

Штатное расписание загружается из семи отдельных CSV-вкладок для 5–11 классов. Большой XLSX на бесплатном тарифе превышал лимит CPU, поэтому старый источник полной книги отключается. Записи одной вкладки сохраняются одним атомарным SQL batch. Ссылки, добавляемые через Cloudflare-админку, тоже должны содержать `gid` нужной вкладки. Когда в книге замен появляется вкладка нового месяца, добавь её через «Источники → Замены».

В зависимости Worker включён `tzdata`: в Pyodide нет системной базы часовых поясов. Московский часовой пояс
и календарь праздников для текущего учебного года подготавливаются при создании Python snapshot, чтобы первый
запрос к опубликованному расписанию укладывался в лимит CPU.

Это обработка с повторами и возможной задержкой, а не математическая гарантия доставки: если один импорт каждый раз превышает лимит CPU, он не завершится. Проверяй Worker CPU и Cron Events в панели после запуска. Заблокировавшему бота пользователю Telegram физически не доставит сообщение; такая запись убирается из очереди, чтобы не блокировать остальных.

Проверка уведомлений пропускает пользователей без актуального класса и с полностью отключёнными уведомлениями;
они не замедляют круг после массового импорта. Рассылки при этом доступны всем импортированным пользователям.
При большом числе активных пользователей круг может оказаться длиннее интервала напоминания: напоминание до начала
урока тогда можно пропустить. Постоянная очередь повторяет уже сформированные сообщения, но не гарантирует формирование
напоминаний вовремя при любой нагрузке. При росте аудитории нужно пересматривать размер пакета / архитектуру планировщика.

Cloudflare сейчас не требует переходить на платный тариф после trial: Workers Free ограничен 100 000 запросов в сутки и 10 мс CPU на вызов; D1 Free включает 5 млн прочитанных строк и 100 000 записанных строк в сутки и 5 ГБ общего хранилища. Для школьного бота это должно быть большим запасом при умеренном использовании, но при исчерпании квот запросы начинают завершаться ошибкой. Это бесплатный тариф, а не SLA; условия сервиса могут со временем меняться.

## 1. Создать D1

Нужны Node.js и `uv`. Если `uv` ещё не установлен на Linux/macOS, установи по официальной инструкции Astral, затем открой новый терминал. В корне репозитория:

```bash
npx wrangler login
npx wrangler d1 create lyceum44-schedule
```

Wrangler покажет `database_id`. В `wrangler.jsonc` замени `REPLACE_WITH_D1_DATABASE_ID` на этот ID. Имя базы оставь `lyceum44-schedule`.

Установи/синхронизируй Python-зависимости для Worker и накати схему. Для локального запуска обычного бота через SQLite/PostgreSQL используй `uv sync --all-groups` (добавятся локальные драйверы); Cloudflare-деплою они не нужны.

```bash
uv sync
npx wrangler d1 migrations apply lyceum44-schedule --remote
```

Миграция создаёт таблицы приложения и постоянное D1-хранилище FSM. Схема локальной SQLite/PostgreSQL сама по себе не переносит прошлых пользователей. При первом запуске расписание и источники будут загружены из настроенных Google Sheets; подписчики, их выбранные классы и старые логи из Render нужно переносить отдельно, если они нужны.

### Перенос старых пользователей

Для SQLite сначала проверьте количество без изменений:

```bash
uv run --group local python -m scripts.import_cloudflare_users --sqlite /absolute/path/old-bot.db
```

Для старого PostgreSQL вместо `--sqlite …` укажите `--env-file /absolute/path/old.env` с его `DATABASE_URL`.
После проверки повторите команду с `--apply`. Нужна действующая авторизация Wrangler.
Скрипт добавляет только отсутствующие Telegram ID, повторный запуск безопасен; настройки существующих
пользователей D1 не перезаписываются. Класс переносится только для текущего учебного года и если класс/профиль
есть в загруженном расписании. Старые классы не повышаются автоматически. Уведомления и рассылка при импорте
не отправляются, токен бота не нужен, ID и пароли в вывод не попадают. Резервные копии базы не коммитьте.
Telegram Bot API не предоставляет список всех прежних подписчиков: без старой базы восстановить его нельзя.

## 2. Секреты и настройки

Добавь секреты, не записывая их в Git:

```bash
npx wrangler secret put BOT_TOKEN
npx wrangler secret put ADMIN_IDS
npx wrangler secret put TELEGRAM_WEBHOOK_SECRET
```

`BOT_TOKEN` — новый токен из BotFather. Так как ранее токен попадал в публичный репозиторий и бот был захвачен, сначала отзови старый токен командой `/revoke` в BotFather и используй новый. `ADMIN_IDS` — Telegram ID администраторов через запятую. `TELEGRAM_WEBHOOK_SECRET` — случайная строка из латинских букв, цифр, `_` и `-`, длиной 32–64 символа; сохрани её отдельно, она понадобится при установке webhook. Никогда не добавляй токен в `wrangler.jsonc`, `.env.example` или Git.

Обычные настройки лежат в `wrangler.jsonc`: часовой пояс, учебный год, время звонков и расписание синхронизации. Для смены Google-таблиц отредактируй `BOOTSTRAP_*_SOURCES_JSON` или константы официальных источников в `app/services/sync.py`, затем задеплой заново. Секреты Workers задаются через `wrangler secret`, не через `vars`.

## 3. Запуск локально и деплой

Первый запуск Wrangler попросит авторизовать аккаунт. Для локальной эмуляции запусти скрипт (он применит миграцию только к локальной D1 и отключит автозагрузку `.env`):

```bash
bash scripts/cloudflare-dev.sh
```

Не используй production-токен для локальной эмуляции. Для первого рабочего запуска:

```bash
bash scripts/cloudflare-deploy.sh
```

Команда напечатает адрес вида `https://lyceum44-schedule-bot.<твой-subdomain>.workers.dev`. Проверь `https://...workers.dev/health` — ответ должен быть `ok`.

## 4. Подключить Telegram webhook

Останови все старые экземпляры бота: локальный long polling, Render Web Service/Background Worker и любые другие запуски с этим токеном. Для webhook нельзя одновременно запускать `getUpdates` — Telegram вернёт конфликт.

Задай значения в терминале (команда не изменяет файлы проекта):

```bash
export BOT_TOKEN='токен-из-BotFather'
export CF_WORKER_URL='https://lyceum44-schedule-bot.<твой-subdomain>.workers.dev'
export TELEGRAM_WEBHOOK_SECRET='та-же-строка-которая-была-передана-wrangler-secret'
curl --fail --silent --show-error \
  "https://api.telegram.org/bot${BOT_TOKEN}/setWebhook" \
  --data-urlencode "url=${CF_WORKER_URL}/telegram" \
  --data-urlencode "secret_token=${TELEGRAM_WEBHOOK_SECRET}" \
  --data "drop_pending_updates=true"
```

В ответе Telegram ожидается `"ok":true`. Проверить состояние webhook можно так, не публикуя токен:

```bash
curl --silent "https://api.telegram.org/bot${BOT_TOKEN}/getWebhookInfo"
unset BOT_TOKEN TELEGRAM_WEBHOOK_SECRET
```

Первую синхронизацию Worker запускает Cron; её результат смотри через `npx wrangler tail` и Telegram `/admin`. Не запускай старый polling-процесс параллельно.

## Что будет работать

Актуальные источники замен, обнаружение новых месяцев и диагностика:
[replacements.md](replacements.md). Автоматика на Cloudflare не скачивает всю книгу XLSX:
список вкладок проверяется отдельно, месяцы импортируются по одному в CSV.

- Ответы на команды и кнопки приходят через webhook; состояния админских диалогов сохраняются в D1.
- Расписание, замены, профили учеников, календарь, состояние публикации и отметки отправленных уведомлений находятся в D1.
- Cron обрабатывает следующий источник раз в 2 минуты и до двух пользователей с уведомлениями в отдельном запуске раз в 2 минуты; рассылки лежат в D1 и уходят постепенно, временно недоставленные уведомления отправляются повторно.
- Кнопки «Сегодня» / «Завтра», навигация по дням, выбор даты в неделе, выбор параллели и класса, настройки с переключателями, звонки и помощь работают в одном редактируемом сообщении. Админский ввод отменяется кнопкой или `/cancel`.
- Главное меню содержит четыре действия: расписание, замены, друзья, настройки. Уведомления, выбор класса,
  звонки, помощь и админ-панель находятся внутри настроек. Друзья хранятся в D1 отдельно для каждого владельца;
  по три карточки на страницу, расчёт одного класса переиспользуется внутри страницы. Ввод друзей тоже сохраняется в D1.
- Публикация расписания не требует текста или рассылки. Объявление пользователям — отдельная необязательная функция «Рассылка» в админ-панели.
- Локальный запуск на компьютере и Render остаются отдельными вариантами. Не включай их одновременно с Cloudflare на одном bot token.
