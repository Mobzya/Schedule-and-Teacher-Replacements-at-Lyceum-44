# Замены: источники и диагностика

Проверено 02.11.2026. Рабочий деплой — Cloudflare Workers + D1, а не Render.

## Почему перестали появляться новые замены

Книга та же, но каждая месячная вкладка имеет свой `gid`:

| Вкладка | gid |
| --- | --- |
| Сентябрь 2026 | `1372611677` |
| Октябрь 2026 | `1829005493` |
| Ноябрь 2026 | `1397336121` |

Присланная ссылка открывала сентябрь; автоматический источник был закреплён за октябрём.
Оба источника продолжали успешно проверяться, но ноябрьских дат в них не было.
Во время диагностики новая вкладка содержала 58 замен: 26 на 2 ноября и 32 на 3 ноября.
В её декоративной строке оставалось слово «октябрь»; парсер ориентируется на даты строк,
а не на это оформление.

Актуальная вкладка: [ноябрь 2026](https://docs.google.com/spreadsheets/d/1bZlIyg9_0JYLnN2WTD3SMxg4zHWe-PaqWDGYnZV1hEg/edit?gid=1397336121).

## Автоматическое обнаружение месяцев

`SyncService.discover_replacement_sources()` читает `/htmlview` официальной книги раз в 6 часов.
Из публичного списка берутся только видимые вкладки с названием
`Замена <месяц> <год>` / `Замены <месяц> <год>` настроенного учебного года.
Названия с `(копия)`, служебные листы и прошлый учебный год пропускаются.
Скрипты страницы не выполняются, внешние `pageUrl` игнорируются: ссылки строятся из
известного ID книги и числового `gid`.

Каждый месяц — отдельный CSV-источник `official-replacements-YYYY-MM`.
Отключённые источники не включаются повторно, ручные ссылки не переписываются,
уже сохранённые месяцы не удаляются. Новый месяц подключается без изменения кода.
Один Cron-вызов выполняет **либо** обнаружение вкладок, **либо** импорт одного CSV.
Текущий управляемый месяц получает каждый второй импортный такт — примерно раз в 4 минуты;
остальные источники обходятся по кругу. Обнаружение новых вкладок иногда занимает отдельный такт.

При ошибке обнаружения в D1 сохраняется только тип ошибки, следующая попытка — через 15 минут.
Известные источники продолжают обновляться между попытками. При ошибке отдельного импорта
его последний успешный snapshot остаётся; новые данные заменяют его атомарно.
Проверка учебного года не отключена. Успешный пустой лист по-прежнему может означать отсутствие
замен, поэтому намеренное удаление строк администрацией отражается в данных.

Это не гарантия работы при любом изменении Google. Если школа закроет доступ, изменит название
книги/вкладок или структуру таблицы, потребуется ручная проверка. Новая вкладка должна быть
видимой; скачивание всей книги XLSX не используется для автоматического обнаружения в Worker.

## Проверка без токена Telegram

В боте: `Настройки → Админ → Источники → нужный месяц → Проверить сейчас`.
Проверьте дату последней успешной синхронизации и отсутствие ошибки.
После публикации `ready` обновления замен применяются без повторной публикации/рассылки.

Для проверки реальных таблиц во временной локальной базе:

```bash
uv run --group local python -m scripts.check_sources
uv run --group local python -m scripts.check_sources --replacements-only
```

Команда не использует production D1 и не отправляет Telegram-сообщения.
Вторая команда проверяет только замены, даже если основная книга расписания закрыта.

На Cloudflare (нужна авторизация Wrangler):

```bash
npx wrangler d1 execute lyceum44-schedule --remote --command "SELECT name,enabled,last_status,last_error,last_success_at FROM data_sources WHERE source_type='replacements'"
npx wrangler d1 execute lyceum44-schedule --remote --command "SELECT key,value FROM app_state WHERE key LIKE 'replacement_discovery_%'"
```

`replacement_discovery_at` — время следующей проверки; `replacement_discovery_error` —
пустая строка при успехе или тип последней ошибки. Для повторной проверки списка на ближайшем
импортном Cron очистите время, не удаляя источники и их данные:

```bash
npx wrangler d1 execute lyceum44-schedule --remote --command "UPDATE app_state SET value='' WHERE key='replacement_discovery_at'"
```

Не сбрасывайте `sources_bootstrap_revision` без необходимости: bootstrap и обнаружение новых
месяцев — разные операции. Повторный bootstrap не нужен для обычной смены месяца.
Не запускайте `app.main` с production-токеном, пока работает Cloudflare webhook.
